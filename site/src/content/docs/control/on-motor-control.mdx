<WhyItMatters>
Open another team's code or a vendor example and the elevator may have no `PIDController` at all. The same PID and feedforward are running inside the motor controller.
You do not need to master this. You need to recognize it, because you will meet it often.
</WhyItMatters>

## Same math, different place

Everything in this track runs on the roboRIO, 50 times a second. The TalonFX can run the same kind of loop itself, about 1000 times a second. You send it a target, and it computes the voltage.

| | On the roboRIO (this site) | On the motor controller |
|---|---|---|
| Where the loop runs | Your Java, in `periodic()` or a command | Inside the TalonFX |
| How often | About 50 Hz (every 20 ms) | About 1 kHz |
| Gains | Your own units, such as volts per RPS | Volts per rotation (and per rotation per second) of the mechanism, after the configured ratios |
| How you tune | Edit constants in Java, then redeploy | Edit gains in a config (Phoenix Tuner X can change them live) |
| What you graph | Your own NetworkTables signals | Signals the device reports, such as position, velocity, and closed-loop error |
| Pros | You can see and log every piece | Faster, and less code and CAN traffic |
| Cons | Slower loop, and more code to write | Less visible, and tied to CTRE hardware |

## Reading the configuration

Gains live in a slot, and you can recognize the familiar names.

| Item | Meaning |
|---|---|
| `Slot0Configs` | A set of gains: `kP`, `kI`, `kD`, `kS`, `kV`, `kA`, `kG` |
| `VelocityVoltage` | Request: hold this velocity, in rotations per second |
| `PositionVoltage` | Request: go to this position, in rotations |
| `MotionMagicVoltage` | Request: go to this position along a profile |

**Motion Magic** is the on-motor version of lesson 3.6. It builds a trapezoid-shaped profile inside the controller. `MotionMagicConfigs` holds its cruise velocity, acceleration, and jerk (how quickly acceleration may change).

```java
// 2026: gains and profile go in the configuration, once
var config = new TalonFXConfiguration();
config.Slot0.kP = 24.0;
config.MotionMagic.MotionMagicCruiseVelocity = 80;   // rotations per second
config.MotionMagic.MotionMagicAcceleration = 160;    // rotations per second squared
motor.getConfigurator().apply(config);

// then each loop, send only the target
motor.setControl(new MotionMagicVoltage(0).withPosition(10.0)); // rotations
```

The numbers are examples only. The code never calculates a voltage. It sets up, then asks.

<GoDeeper title="how mechanism units get there">
The controller works in motor rotations unless told otherwise. A feedback ratio setting converts motor rotations to mechanism rotations, so gains then refer to the mechanism. Distance-based mechanisms like an elevator still need a conversion from rotations to meters in your own code.
</GoDeeper>

## Which should you use?

This team's training uses roboRIO-side control, so you can see and graph every piece: the error, the feedforward, the profile. That makes you a better debugger.
Many competition robots use on-motor control, and the ideas transfer directly: the same gains, the same tuning order, the same graphs. Learn one, and you can read the other.

## Recap

<RecapCard>
- On-motor control runs the same PID and feedforward inside the TalonFX, at about 1 kHz.
- `Slot0Configs` holds `kP` to `kG`; requests like `PositionVoltage` carry the target.
- Motion Magic is a profile running in the motor controller.
- Gains are in rotations and volts of the mechanism, not your own units.
- Both approaches are common. This site teaches roboRIO-side to make everything visible.
</RecapCard>

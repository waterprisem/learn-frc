<WhyItMatters>
The robot is on, the code is running, and the intake still does not spin. Often the robot is simply disabled.
Knowing the modes, and which code runs in each, tells you what the robot can and cannot do at any moment.
</WhyItMatters>

## Four modes

The **Driver Station** (the laptop app that talks to the robot over Wi-Fi) sends the robot its **mode**. Your code does not choose it.

| Mode | What it is for |
|---|---|
| Disabled | The robot is on, code is running, and motors are not driven |
| Autonomous | The robot runs a pre-programmed routine with no driver input |
| Teleoperated | Drivers control the robot with their controllers |
| Test | Checks and tuning outside a match |

At a competition, the field system (FMS) controls the Driver Station, so a team cannot enable its robot during a match on its own.

**Motors are only driven while the robot is enabled.** The three enabled modes are autonomous, teleoperated, and test. While disabled, your code still runs, but motor output is blocked.

## Which methods run when

`Robot.java` has a method for each mode, and the **Init** one runs once when the mode starts.

| Mode | Runs once on entry | Runs every ~20 ms |
|---|---|---|
| Any mode | | `robotPeriodic()` |
| Disabled | `disabledInit()` | `disabledPeriodic()` |
| Autonomous | `autonomousInit()` | `autonomousPeriodic()` |
| Teleoperated | `teleopInit()` | `teleopPeriodic()` |
| Test | `testInit()` | `testPeriodic()` |

`robotPeriodic()` runs in every mode, including disabled. Each mode also has an `Exit` method that runs once when the mode ends.

## The one line that makes commands work

In the team's command-based code, most `Periodic` methods are empty. The work happens in one place.

Because `robotPeriodic()` runs while disabled, subsystems' `periodic()` still runs, so telemetry and logging keep updating. Commands that need a motor to move produce no motion until the robot is enabled.

## Checkpoint

<Checkpoint lesson="1.13">

<details>
<summary>The robot is disabled. Does your subsystem's `periodic()` still run? Do the motors move?</summary>
Yes, it still runs, because the scheduler runs from `robotPeriodic()` in every mode. The motors do not move, because output is only driven while enabled.
</details>

<details>
<summary>What would happen to your commands if `CommandScheduler.getInstance().run()` were deleted from `Robot.java`?</summary>
Nothing would run. Triggers would never be checked, commands would never execute, and subsystem `periodic()` methods would never be called.
</details>

</Checkpoint>

## Recap

<RecapCard>
- The Driver Station sets the mode: Disabled, Autonomous, Teleoperated, or Test.
- Motors are only driven while enabled. Code, including subsystem `periodic()`, still runs while disabled.
- `robotPeriodic()` runs in every mode. Each mode adds its own Init (once) and Periodic (every ~20 ms) methods.
- `CommandScheduler.getInstance().run()` in `robotPeriodic()` is what runs commands.
</RecapCard>

<WhyItMatters>
Robot code does nothing by itself. Every line you write ends up reading a sensor or moving a motor.
When something goes wrong, the first question is "which part is this?", so you need to know the parts before you write code for them.
</WhyItMatters>

## Four jobs

Every part on the robot does one of four jobs.

| Job | Parts | What they do |
|---|---|---|
| **Power** | Battery, main breaker, PDH | Supply electricity and share it out safely |
| **Brain** | roboRIO, radio | Run your code and keep it in touch with the drivers |
| **Muscles** | Motors | Turn electricity into motion |
| **Senses** | Encoders, limit switches, the IMU, cameras | Tell the code what the robot is doing |

Your code lives in the brain. It reads the senses, decides, and commands the muscles, 50 times every second.

## Checkpoint

<Checkpoint lesson="1.1">

<details>
<summary>Point to any part and describe it in one sentence. Can you do all ten?</summary>
Use **Find it** above as your check. On a real robot, do the same thing by touching each part with the robot switched off.
</details>

<details>
<summary>Which parts does your code talk to directly?</summary>
Motor controllers and sensors. The battery, breaker, and radio have no code of their own; your code only notices them when they fail.
</details>

</Checkpoint>

## Recap

<RecapCard>
- A robot has four kinds of parts: power, brain, muscles, and senses.
- Your code runs on the roboRIO. It reads sensors and commands motors.
- Each part has a card: what it is, where it sits, how it connects, how code sees it, and how it fails.
</RecapCard>

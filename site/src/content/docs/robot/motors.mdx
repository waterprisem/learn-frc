<WhyItMatters>
Release the button on a shooter wheel and it keeps spinning for several seconds. Release it on an arm and the arm sags.
Both behaviors come from one setting in the motor controller, and you choose it in code.
</WhyItMatters>

## Your code talks to a controller, never to the motor

A **motor controller** sits between your code and the motor. It receives a request over CAN (a voltage, a velocity or a position), switches battery power into the motor, and reports sensor data back.

Modern FRC motors are **brushless**. They have no moving electrical contacts, so electronics must switch power into the motor's windings in the right order as the shaft turns. That is the controller's job, and you never do it yourself.

The **Kraken X60** has its controller, a **TalonFX**, built into the housing. In code it is one object: `new TalonFX(canId)`.

<GoDeeper title="what brushless means">
A brushless motor is driven with three-phase power: three wires, each switched on and off in a repeating pattern. The controller uses the rotor's position to time each switch.
This lesson does not need the math. You only need to know that the controller does it.
</GoDeeper>

## Coast or brake

When your code commands 0 output, the motor does one of two things. This is its **neutral mode**.

- **Coast:** the controller lets the motor spin freely. A flywheel keeps turning and slows down gradually.
- **Brake:** the controller connects the motor's windings together, so the motor resists being turned.

Pick coast for a flywheel, because braking would waste time between shots. Pick brake for an arm, an elevator or a drivetrain, because you want them to stop and stay put.

Brake does not lock anything in place. It only resists motion, so an arm in brake mode can still sag slowly under gravity.

You set it once, when the subsystem is created:

```java
config.MotorOutput.NeutralMode = NeutralModeValue.Brake;
```

Which direction counts as positive is also a setting (`InvertedValue`), so you can fix a backwards motor in configuration instead of rewiring.

## Current limits

**Current** is how much electric charge flows per second, measured in amps (A). A stalled Kraken, one forced to stop while powered, can draw over 300 A. A **current limit** in the controller's configuration caps that, protecting the motor and the mechanism. Lesson 1.3 covered why the battery and wiring need protecting too.

## Recognizing other hardware

You will see other motors in the pits. This team's labs all use TalonFX, so you only need to recognize them.

| Hardware | What it is | In code |
| --- | --- | --- |
| NEO, NEO Vortex | REV brushless motors | `SparkMax` / `SparkFlex` |
| SPARK MAX, SPARK Flex | Separate controller boxes wired to the NEO and NEO Vortex | REVLib |
| Falcon 500 | Older CTRE motor with a TalonFX built in | `TalonFX` |

## Recap

<RecapCard>
- Your code sends requests to the motor controller over CAN. It never drives the motor.
- The Kraken X60 has a TalonFX controller and a rotor sensor built in.
- Coast spins down freely (flywheels). Brake resists motion (arms, elevators, drivetrains) but does not lock.
- A current limit caps the amps a stalled motor can draw.
- NEO and NEO Vortex use separate SPARK controllers. The Falcon 500 is an older TalonFX motor.
</RecapCard>

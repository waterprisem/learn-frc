<WhyItMatters>
Release the button that raised an elevator and, with no command left, the motor gets nothing and the elevator sags. A **default command** is the answer to "what should this mechanism do when nobody is asking?"
</WhyItMatters>

## The rule

`subsystem.setDefaultCommand(command)` gives a subsystem one command that the scheduler runs whenever no other command requires that subsystem.

1. A button's command starts and takes the subsystem. The default is interrupted.
2. The button command ends or is cancelled. The default starts again, automatically.

A default command must require its subsystem, and it normally never finishes. A default that finishes leaves the subsystem with nothing to do again.

## Home is a default

So `Home` is not a button. It is what the robot does whenever no held command is using the mechanisms. When the driver lets go of A, X, or Y, the held action ends and the defaults take the robot back to Home. The lab checks this: after releasing each button, confirm the robot returns Home.

Lab 11 goes one step further: the arm and elevator defaults read the active side, so the robot rests on the side the driver last chose.

## Checkpoint

<Checkpoint lesson="5.4">

<details>
<summary>Why is Home implemented as default commands instead of a button?</summary>
Home is the resting state, not something the driver asks for. A default command applies it automatically whenever no held action is using the mechanisms, and brings it back when the driver releases a button.
</details>

<details>
<summary>What happens to the default when a button command starts, and when it ends?</summary>
The button command requires the same subsystem, so the default is interrupted. When the button command ends, the default starts again by itself.
</details>

<details>
<summary>Why must a default command require its subsystem?</summary>
Requirements are how the scheduler decides the default is idle and a button command may replace it. Without the requirement the default would run at the same time as the button command and both would drive the motor.
</details>

</Checkpoint>

## Recap

<RecapCard>

- A default command runs when nothing else requires the subsystem, and restarts when the other command ends.
- It must require its subsystem and normally never finishes.
- Use a default to hold a safe resting state, so that state needs no button.
- In Lab 9, Home is the defaults; A, X, and Y are held actions on top.

</RecapCard>

<GoDeeper title="one default per subsystem">

A subsystem has at most one default command. Setting a second one replaces the first. If a default should behave differently by mode, make it read state, as the Lab 11 arm default does with `isFrontIntake`, instead of swapping defaults.

</GoDeeper>

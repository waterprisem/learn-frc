## What a test is

A **test** is a small piece of code that sets up a situation, runs your code, and checks the result with an **assertion**: a line that fails the test if a condition is false. Tests live in `src/test/java`, and the build tool runs them all and reports what passed.

The labs ship two examples. `MiniScorerSimulationTest` (Lab 11) and `ArmSimulationSmokeTest` (Lab 9) create a real subsystem, run its control loop in the WPILib simulator, and assert on the mechanism's state. For example, "within 150 loops the flywheel gets within 4 RPS of its scoring speed" or "the elevator gets within 0.08 m of its height".

## Run it and read a failure

From the project folder run:

```
./gradlew test
```

or use the WPILib command **Test Robot Code** in VS Code. Gradle prints each test as passed or failed, and writes an HTML report under `build/reports/tests`.

A failure looks like the assertion message you wrote, for instance `Flywheel should reach target velocity within tolerance. Best error: 11.3`. Read it in three steps.

1. Which test failed, and which assertion?
2. What number did it get, and what did it expect?
3. Is the code wrong, or did you change a constant the test depends on on purpose?

Because the test uses the real constants, a gain change that makes the flywheel slower can fail it. That is the test doing its job.

## What a passing test does not prove

A passing simulation test says the code behaves inside a model. It does not say the real robot works.

- The simulation does not include a loose belt, a flipped motor, or a real battery.
- The tests check the final reach, not how smooth or safe the motion was.
- They only cover what someone thought to assert.

Treat tests as a quick safety net before you deploy, and still test on the robot.

<GoDeeper title="the Session 9 smoke test">
`ArmSimulationSmokeTest` is called a smoke test because it checks only that the basics work, like turning on a device and watching for smoke. It moves the arm to the amp angle and back home, and asserts the best error is under 4 degrees each time.
It also asserts the first computed voltage is not nearly 0, which catches a controller that is silently doing nothing.
</GoDeeper>

## Recap

<RecapCard>
- A test builds a situation, runs your code, and asserts a result.
- The lab tests step the simulation and assert on mechanism state, such as velocity error or height.
- Run them with `./gradlew test` or **Test Robot Code**.
- Read the failure message: which assertion, which number, and whether the code or a constant changed.
- A passing simulation test does not prove the real robot works.

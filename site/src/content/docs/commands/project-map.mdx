<WhyItMatters>
A mentor points at a robot and asks, "What happens when I press A?" A robot project has dozens of files, and the answer is in exactly one of them.
Knowing what each file is for turns "where is it?" into a ten-second search.
</WhyItMatters>

## What lives where

A robot project follows the same layout every year. Most files are scaffolding you rarely edit; your work goes in the subsystems, commands, and bindings.

| File | What it is for | When it runs |
|---|---|---|
| `Main.java` | Starts the robot program. Scaffolding. | Once, at startup |
| `Robot.java` | The timed entry point. Runs the **command scheduler** every loop and schedules the autonomous command. | `robotPeriodic()` about every 20 ms |
| `RobotContainer.java` | Creates the controller and subsystems and connects buttons to commands. | Built once at startup; `getAutonomousCommand()` when autonomous starts |
| `Constants.java` | Names and numbers (ports, CAN IDs, limits) in one place. | Never runs; other files read it |
| `subsystems/` | One class per mechanism. Owns its hardware (lesson 2.2). | Built once; `periodic()` every loop |
| `commands/` | One class per behavior. | Only while scheduled |
| `deploy/`, `vendordeps/` | Files copied to the roboRIO, and declarations of vendor libraries such as Phoenix 6. | Build and deploy time |

The scheduler is the key: `Robot` runs it once per loop, and it is what starts, runs, and ends everything else. Lesson 2.3 covers how.

<GoDeeper title="generated code versus handwritten code">
Not every file is yours to edit. `Main.java`, most of `Robot.java`, and the Gradle build files are WPILib scaffolding. Vendor libraries live in `vendordeps/`. On the competition robot, the swerve drivetrain classes are generated by CTRE's SwerveGen tool.
You read and use those files, but you rarely rewrite them. Handwritten subsystems, commands, and bindings are where the team's behavior lives.
</GoDeeper>

## Checkpoint

<Checkpoint lesson="2.1">

<details>
<summary>What does Robot.robotPeriodic() do?</summary>
It runs the command scheduler every loop. The scheduler checks triggers, starts and runs commands, and calls each subsystem's `periodic()`.
</details>

<details>
<summary>Where are controller buttons connected to commands?</summary>
In `RobotContainer`, inside `configureBindings()`.
</details>

<details>
<summary>Which files are handwritten robot behavior, and which are scaffolding or generated?</summary>
Handwritten: subsystems, commands, `RobotContainer` bindings. Scaffolding: `Main.java`, most of `Robot.java`, Gradle. Generated: CTRE swerve classes and vendor libraries.
</details>

</Checkpoint>

## Recap

<RecapCard>
- `Robot` runs the scheduler every loop; `RobotContainer` builds the robot and wires buttons to commands.
- Subsystems hold hardware and state, commands hold behavior, and `Constants` holds shared numbers.
- To learn what a button does, start in `configureBindings()` and follow the command.
- Scaffolding and generated files are for reading; your work is subsystems, commands, and bindings.
</RecapCard>

<WhyItMatters>
A driver taps a button to fire once, holds a button to run the intake, and presses another to turn a mode on and off.
Each of those is the same button hardware wired to the same scheduler with a different binding. Picking the wrong one means a shooter that never stops or a mechanism that stops too soon.
</WhyItMatters>

## A trigger is a condition

A **Trigger** is a true/false condition the scheduler checks every loop. A button is a trigger. So is a sensor reading or `flywheelAtTarget`.

A **binding** ties a trigger to a command. The scheduler watches for the trigger to change, not for it to be true. Going from false to true is the "press" edge. Going from true to false is the "release" edge.

`CommandXboxController` gives you triggers for every button: `controller.a()`, `controller.b()`, `controller.leftBumper()`, and so on.

## Which binding to use

| Binding | Starts when | Ends when |
|---|---|---|
| `onTrue(cmd)` | Trigger becomes true | The command finishes on its own. Release does nothing. |
| `whileTrue(cmd)` | Trigger becomes true | Trigger becomes false (`end(true)`), or the command finishes |
| `toggleOnTrue(cmd)` | Trigger becomes true while the command is off | The next press, or the command finishes |
| `onFalse(cmd)` | Trigger becomes false | The command finishes on its own |

Use `whileTrue` for "run while I hold it", like a flywheel or intake. Use `onTrue` for one-shot actions that finish themselves. A command that never finishes, bound with `onTrue`, never stops on its own.

## Default commands

A **default command** runs on a subsystem whenever no other command requires it. When a button's command takes over, the default is interrupted. When that command ends, the default starts again. Lesson 5.4 covers them in depth.

## Do it for real

<DoItForReal tools="WPILib simulator">
In the **Lab 3** solution, change one binding and watch the difference.

1. Open `labs/Session 3 - Open-Loop Flywheel with TalonFX/solution` and find `configureBindings()` in `RobotContainer.java`.
2. Change the A binding from `whileTrue` to `onTrue`.
3. Run **WPILib: Simulate Robot Code**, set the Driver Station to **Teleoperated**, and tap keyboard <kbd>Z</kbd> (Xbox **A**).
4. Change it to `toggleOnTrue` and try again. Put it back to `whileTrue` when done.

**You know it worked when** with `onTrue` the wheel keeps spinning after you release A, because this command never finishes. With `toggleOnTrue` a second tap stops it.

**On a real robot, also check**

- Anything you bind with `onTrue` or `toggleOnTrue` has a way to stop (a finish condition, a second press, or another command).

## Checkpoint

<Checkpoint lesson="2.5">

<details>
<summary>Why does the lab use whileTrue and not onTrue for the A button?</summary>
`whileTrue` cancels the command when A is released, which runs `end(true)` and sets 0 V. This command never finishes on its own, so with `onTrue` the wheel would keep spinning after release.
</details>

<details>
<summary>What does the default command do in Lab 3?</summary>
It requests 0 V whenever no button command owns the flywheel, so the idle state is always safe.
</details>

## Recap

<RecapCard>
- A Trigger is a true/false condition; a binding ties it to a command.
- `onTrue` starts on press, `whileTrue` also cancels on release, `toggleOnTrue` flips on each press, `onFalse` starts on release.
- Use `whileTrue` for hold-to-run commands that never finish on their own.
- A default command runs whenever nothing else requires the subsystem.
</RecapCard>

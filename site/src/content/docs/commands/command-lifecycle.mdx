<WhyItMatters>
You hold a button, the flywheel spins, you let go, and it stops. Nothing in your code checks the button.
The stop happens because a command has a fixed lifecycle, and the scheduler calls its methods at exactly the right moments.
</WhyItMatters>

## Four methods, four moments

A **command** is a class that extends `Command`. The **command lifecycle** is the set of methods the scheduler calls on it, in a fixed pattern.

| Method | When it runs | Typical job |
|---|---|---|
| `initialize()` | Once, when the command starts | One-time setup |
| `execute()` | Every loop (every 20 ms) while the command is running | The repeating work |
| `isFinished()` | Right after each `execute()` | Return `true` when the job is done |
| `end(boolean interrupted)` | Once, when the command stops | Leave the mechanism safe |

You write these methods. You never call them yourself: the scheduler does (lesson 2.4).

## Stepping through the loop

Say a button is pressed at tick 3 and released at tick 6. A **tick** is one 20 ms loop. This command's `isFinished()` always returns `false`.

| Tick | Button | `initialize()` | `execute()` | `isFinished()` | `end()` |
|---|---|---|---|---|---|
| 1 | up | | | | |
| 2 | up | | | | |
| 3 | **pressed** | runs | runs | false | |
| 4 | held | | runs | false | |
| 5 | held | | runs | false | |
| 6 | **released** | | | | `end(true)` |
| 7 | up | | | | |

The press starts the command, and `execute()` runs on that same tick. On tick 6 the scheduler cancels the command before it can execute again, so the last `execute()` is tick 5.

## What `interrupted` means

`end()` is the only method that gets an argument.

- **`true`**: something outside stopped the command. The button was released, or another command took over its subsystem.
- **`false`**: the command stopped itself because `isFinished()` returned `true`.

Either way, `end()` runs once. That is why safe cleanup, such as setting a motor to 0 V, goes in `end()` and not in the button code.

<details>
<summary>You hold A for one second, then release it. What is the call sequence?</summary>
`initialize()` once, `execute()` about 50 times (once per 20 ms loop), then `end(true)` once when the release cancels the command.
</details>

<details>
<summary>Why does this command put 0 V in `end()` instead of in a button handler?</summary>
`end()` runs on every way the command can stop: release, another command taking over, or finishing. One place covers all of them, so the mechanism is always left safe.
</details>

</Checkpoint>

## Recap

<RecapCard>
- `initialize()` runs once, `execute()` every 20 ms, `isFinished()` after each `execute()`, `end()` once.
- A command that starts on a tick also executes on that tick. A cancelled command does not execute on the tick it is cancelled.
- `end(true)` means stopped from outside. `end(false)` means `isFinished()` returned `true`.
- Put safe cleanup in `end()`.
</RecapCard>
